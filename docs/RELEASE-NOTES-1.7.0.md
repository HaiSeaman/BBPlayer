## ⚡ v1.7.0 — 打开更快，设置不再丢

本次更新做了一件用户最能直接感受到的事：**点开就出现窗口**，不再"点了半天没反应"。
同时修掉了一个藏得很深的严重 BUG——它一直在偷偷让你的**音量设置每次重启都白设**。

## ✨ 改进

### ⚡ 启动体感优化
- **窗口立即出现**：以前窗口要等到画面第一帧画完才肯露面，那几秒里你眼前什么都没有，
  感觉像卡住了；现在窗口的"壳"在启动瞬间就亮出来（底色与界面一致，不会闪白），内容随后浮现。
- **启动关键路径减负**：音频引擎、画面比例计算等不再堵在"第一帧"之前，挪到首帧之后再完成。
- **封面查找不再卡主进程**：以前读封面图是同步阻塞的，多窗口下会连带卡住所有窗口，现改为异步。

### 🛡️ 修复了一个"设置永远存不住"的严重 BUG
- **症状**：把音量设到 200%，重启软件又变回 100%；字幕字号、倍速按钮文字、菜单选中状态
  也一律恢复不了。
- **原因**：启动时恢复设置的函数，调用了定义在它**后面**的变量，触发 JavaScript 的
  "暂时性死区"报错；而这个错误被内部的保护代码悄悄吞掉了，只打了一行日志，所以一直没人发现。
- **结果**：从这个版本起，音量、字幕样式、倍速、播放模式等设置**真正会被记住**。

### 🐛 其他 BUG 修复
- **双击已打开过的视频没反应**：文件已在播放列表中时，以前点它毫无动静（像软件死了），
  现在会直接切到那个视频播放——这条正是"双击关联文件"最常用的路径。
- **清空观看历史后又自己冒回来**：播放中清空历史，5 秒后当前视频又被写回去了，现在不会了。
- **小写 `dialogue:` 的 ASS 字幕一条都显示不出来**：格式识别对大小写敏感导致整份字幕被误判，
  现已修正。
- **极少数视频被误判成纯音频**：会被套上音乐界面、盖住画面且再也退不出来；现在会自动纠正。
- **换片后第一句字幕偶尔不显示**：新片首句若与上一部最后一句文字相同会被误判为"无需重绘"，已修。
- **播放列表状态错位**：视频文件被删除或格式不支持时，列表高亮会指向没在播的那一条，现在会回退。

### 🔒 安全加固
- 封面读取接口补上文件类型白名单，堵住一条可被滥用来读取任意本地图片的通道。
- 截图保存增加载荷上限；同时存在的播放器窗口数量加上限。
- 新增主进程异常兜底：不再因为某个小毛病导致**整个播放器直接退出**。
- 页面安全策略（CSP）补齐 `object-src` / `base-uri`。

### 🧠 更省内存
- 音乐播放时的频谱动画不再每帧新建数组，减少垃圾回收抖动与瞬时内存占用。
