# BBPlayer 1.10.0

> English version: [RELEASE-NOTES-1.10.0-EN.md](./RELEASE-NOTES-1.10.0-EN.md)

**一句话**：这个版本给播放器装上了**"打开就自动检查新版本"**（没有更新完全静默，有更新才让你决定）；修好了**窗口拖窄后底部播放栏按钮冲出面板的 UI 错位**；并做了一次全仓库审查，修掉 **11 个真实缺陷**、清理了一批死代码，自动化测试补到 **48 项**。

---

## 🆕 新功能：打开软件自动检查更新

以前要更新只能自己去 Releases 页面看。现在：

1. 软件启动约 3 秒后，在后台静默查询一次 GitHub 最新版本；
2. **没有更新：什么都不弹**，你完全感觉不到（断网、超时、接口报错也一样安静）；
3. **有新版本：弹一个原生窗口**，告诉你"当前版本 → 最新版本"，按钮是「确定更新 / 取消」；
4. 点 **确定更新** 后：自动下载对应安装包（任务栏图标显示进度）→ 下载完自动启动安装程序 → 软件自行退出；
5. 点 **取消** 什么都不会发生，安心看片。

**安装版和便携版分别处理**：

- **安装版**：下载 Setup 安装包，启动后由安装程序覆盖安装；
- **便携版**：下载免安装包到软件所在文件夹并自动启动新版（便携软件无法在运行中替换自己，旧文件可以自行删除）。

**为什么不用 electron-updater**：本项目发布物里没有 `latest.yml`，引入它还要改发布流程、加一堆运行时依赖，和"运行时零依赖"的纪律冲突。所以直接用 Electron 自带的网络能力实现，代码只有一个小文件 `updater.js`。

## 🩹 修复：窗口拖窄后底部播放栏错位

**你能感觉到的现象**：把播放窗口拖窄，底部那条悬浮功能栏里的按钮**不跟着收**；窗口越窄，按钮越往右挤，最后直接冲出胶囊面板、被窗口边缘裁掉一半——这就是你说的 UI 错位。

**原因（大白话）**：功能栏的**外框**宽度会跟着窗口缩，但里面那排按钮是**写死尺寸、而且不允许换行**的。实测这排按钮全摊开需要约 **787px**，所以窗口窄到 870px 左右就开始互相挤压；到最小窗口 480px 时，右侧按钮组比面板宽出 **305px**，其中 **281px 已经跑到窗口外面**被裁掉。

**修复后**：

- 按钮、时间显示不再被压扁变形，始终是原来的大小；
- 窗口变窄时自动收紧间距和控件尺寸；
- 一排实在放不下时，自动变成**上下两排居中**——所有按键都还在，一个都不会丢；
- 功能栏变高后，字幕和"跳转续播"提示会同步上移，不会被面板挡住。

**实测数据**（无界面量取 16 档窗口宽度）：

| 窗口宽度 | 1280 | 900 | 640 | 480 |
|---|---|---|---|---|
| 修复前：超出面板 | 0 | 0 | 145px | **305px**（其中 281px 出窗） |
| 修复后：超出面板 | 0 | 0 | **0** | **0** |

## 🔧 全量审查修复的 11 个缺陷

| # | 问题 | 修法 |
|---|---|---|
| 1 | 老格式转码兜底成功后画面**停住**，图标还显示"播放中" | 换播放源会让播放器回到暂停态，且不会触发"暂停"事件；现在换源后按原状态自动恢复播放 |
| 2 | 软件已开着时，**双击另一个视频毫无反应** | 旧逻辑只在"文件已在列表里"时才切播；现在双击/选择文件打开一律立即播放 |
| 3 | 清空播放列表后，**空窗口里标题栏也会自动隐藏** | 清空时播放器的源地址会被浏览器解析成网页地址，旧的"是否为空"判断失效；改用真实加载状态判断 |
| 4 | **右键点进度条也会跳转** | 只响应左键 |
| 5 | 音乐界面**封面阴影/光晕全部消失** | 阴影变量被重复拼接，整条样式非法作废；已改正 |
| 6 | 第二个实例可能**闪一下黑窗**，还会重复跑缓存清理和更新检查 | 未抢到单实例锁的进程直接返回 |
| 7 | **便携版点"确定更新"后毫无反应** | 新版本会撞上旧进程的单实例锁而秒退；改用系统级"退出后再启动" |
| 8 | 更新下载遇到**半开连接时永远卡住** | 增加 30 分钟超时兜底（约 57KB/s 也能下完 100MB） |
| 9 | 更新包路径与完整性可被发布信息利用 | 文件名只取纯文件名（防目录穿越）+ 用发布信息里的大小校验完整性 |
| 10 | 截图默认文件名可能带 `:` 等 Windows 非法字符 | 统一替换非法字符、去掉结尾的点和空格 |
| 11 | 转码缓存可能**删掉正在播的产物**（拖进度失败） | 最近 10 分钟用过的产物不再淘汰 |

## 🧹 死代码与重复代码清理

- 删除两条**永远不会生效**的键盘焦点样式（`div` / `span` 根本无法获得焦点，实测 `tabIndex` 就是 -1）；
- 删除与 `show: true` 重复的窗口显示逻辑、重复的 `row-gap`、重复的文件大小判断；
- 合并两个逐字相同的"打开文件夹"按钮处理器；
- 移除没有任何使用者的内部导出（`availableEncoders` 等 3 处）；
- 更正开发者文档里写错的扩展名键列表。

## 🧪 验证

- `npm run verify` **全绿**：扩展名对账、转换层 **35 项**、渲染层 **48 项**（原有 45 项 + 3 条新回归锁）、接线对账（9 个打包文件 / 24 个 API / 18 发 5 收 IPC）全部通过；
- 关键结论都先用**无界面脚本实测**再动手修：空源地址会被解析成网页地址、换播放源不触发暂停事件、Windows 上启动无效 exe 会同步报错；
- 修好了测试脚本自身的一个隐患：有两个用例把异步函数交给同步断言包装，**失败会被吞掉、显示"通过"**——现在已改为真正等待。

## ⚠️ 如实说明

- 下载的安装包**没有数字签名**，Windows 可能弹一次 SmartScreen 提示，点"仍要运行"即可；
- 自动更新只信任固定的 GitHub 仓库，**不做签名校验**（账号被盗时仍有风险）；
- 下载过程中没有"取消"按钮（网慢只能关掉软件），也不支持断点续传；
- 便携版无法在运行中替换自己：新版会放在旧文件旁边，旧文件要你自己删；不删的话下次打开旧文件还会提示一次；
- 以后发版**必须手动改 `package.json` 的版本号**再打包（本版已改为 1.10.0）。
